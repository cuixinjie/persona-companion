# 访谈与补问指南

## 选择一个具体问题

先看最影响下一次交流的情境，其次看有依据的冲突，最后看其他空白。只问一个能区分候选解释的问题，尽量锚定用户提过的人、时期或场景。一个问题只要求回忆一件具体的事，补充理由应放在问题之外。只有为了澄清同一事件的背景时才并列备选。使用实际结论 ID 关联问题，没有候选时留空。

把“是否记得”和具体想了解的内容合成一个问句，例如“你还记得阿林某次催你报平安时，当时发生了什么吗？”写下第一句后，等用户回答再决定是否需要追问。

| 目的 | 提问方式 |
| --- | --- |
| `missing` | “你还记得某次你不好开口时，阿林接的第一句话吗？” |
| `conflict` | “有一段工作聊天很简短，另一次私下聊得很细。两次当时各在做什么？” |
| `context` | “这句‘晚点说’发生在工作时，还是平时聊天时？” |
| `counterexample` | “你记得他有主动把话题展开的时候吗？那次是什么情况？” |

## 按回答类型记录

- 优先请用户回忆实际发生的一次小事。可询问原话、大致时期、双方关系或前后发生了什么，确实不记得就写未知。回忆用 `recollection`，转述标明由用户回忆，勿包装成逐字原话。
- 用户愿意回答假设时，先表明是假设，例如“如果我们只做一个假设，你觉得他在这种情况下可能怎么说？”回答用 `hypothetical`。无法确定用户表达的是回忆或假设时，只澄清类型。
- “我希望这个数字人物以后先听我说”属于 `style_preference`。如果答复同时包含多种内容，选与当前问题匹配的一种关联该问题，其余分别登记材料，禁止混成同一条历史证据。
- 用户仍愿意访谈、只跳过当前问题时用 `skip`。用户说“先聊聊”、要求结束访谈，或没有可用材料且表示记不起来时，使用 `stop`，保留未知并转到采纳或试聊。用户明确愿意恢复时用 `resume`。已跳过且缺乏依据的事项写进档案的未知栏。恢复后也只在有新核对的相关历史材料且用户愿意回答时重提已跳过的问题。

问题和回答按[本地操作契约](operation-contract.md)保存。回答形成材料草稿，展示类型和你将引用的片段，取得核对后再确认。记下问题会使之前的候选修订号失效；结束本轮补问后重新阅读材料并展示当前候选供采纳。
