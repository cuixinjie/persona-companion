# 03 系统架构

版本 v0.4，2026-11-16。产品基线见 [01](01-需求与范围.md)。本文件技术方案为设计决策 D，宿主实测见 [兼容性记录](compatibility.md)、[M1 验收](m1-acceptance.md) 和 [M2 验收](m2-acceptance.md)。

## 1. 上下文与边界

```text
本地使用者
  ↕ 宿主对话/附件入口
DeepSeek Harness ── 已配置模型（文本与图像，实测范围见兼容性记录）
  ↕ 加载指令与允许的本地工具
人物陪伴 skill：流程指引、问题参考、回复与证据规则
  ↕ 本地辅助脚本的结构化输入输出
资料/人物/记忆服务 ── SQLite 与私有附件目录
```

skill 负责引导，不能单靠提示词保证事务、隔离或权限。辅助脚本负责持久化校验与一致性。宿主负责模型调用、工具授权、附件入口和会话显示。模型输出始终是待校验数据，不直接执行文件操作。

## 2. 已查证与未查证

官方文档确认本地目录形式 `<name>/SKILL.md` 及项目 `.dsh/skills` 等发现入口；技能名采用 kebab-case。具体兼容版本在阶段 0 固定，不把滚动文档当作安装环境事实。[DeepSeek Harness Skills 官方文档](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/skills)（查阅：2026-11-11）。

M0 验证了固定版本的 SDK 图像输入和合成截图识读。M1 验证了该版本的项目技能加载及沙箱内 CLI。用户实际安装、桌面附件交互和宿主历史清理仍待对应阶段验证。

## 3. 模块职责

| 模块 | 职责 | 不负责 |
|---|---|---|
| skill 编排 | 选择流程、提出问题、解释状态、形成候选 | 直接绕过校验写数据 |
| 材料服务 | 导入、来源、说话人、转录核对、撤回 | 推测不明说话人 |
| 归纳与访谈规则 | 按证据形成特征、冲突和问题 | 诊断、完整量表评分 |
| 人物版本服务 | 草稿、采纳、纠错、变更记录 | 将模拟内容变成原人物事实 |
| 对话上下文服务 | 选定人物版本、相关材料、记忆、临时风格 | 跨人物自由检索 |
| 记忆与发展服务 | 新交流记忆、发展候选、开关约束 | 静默改变核心性格 |
| 本地存储与校验 | ID、路径、引用、事务、版本并发、删除 | 提供公网认证服务 |
| 宿主适配说明 | 能力检测、安装、调用方式 | 修改 DeepSeek Harness 核心 |

## 4. 主要数据流

1. 输入附件/文字 → 本地导入登记 → 宿主模型辅助转录 → 用户核对 → 确认材料。
2. 确认材料 → 候选特征与来源引用 → 校验引用/类型 → 补问 → 用户采纳 → 新人物版本。
3. 用户消息 → 绑定人物及版本 → 选择必要上下文 → 宿主模型回复 → 按开关保存交流记忆。
4. 新回忆 → 旧人物知识候选；新互动 → 数字人物记忆/发展候选。两条流不可混为一条。
5. 纠正/撤回 → 使旧结论失效或待复核 → 新版本/上下文刷新 → 后续使用新状态。

## 5. 关键选型及理由（D）

- Markdown skill 与参考文档：适合开源分发和对话式工作流。
- Python 3.11+ 标准库辅助脚本：JSON 契约与 SQLite 可不引入额外数据库服务。M0 实测版本见 [兼容性记录](compatibility.md)。
- SQLite：本地事务、人物隔离、来源关联；不直接依赖宿主会话作为唯一记忆。
- 原始附件存文件，元数据存数据库：避免把图像塞入每轮对话；采用内部生成路径。
- 首版不引入向量数据库、模型训练、Web 后端和常驻公网服务；先按人物、版本、情境与来源筛选。检索质量不足再据测试决定扩展。
- 图像识别优先复用宿主已配置能力。若不支持则阻塞截图验收；不得默默引入第三方 OCR。

## 6. 部署与依赖

每位使用者在自己的 Harness 中安装 skill 包；辅助脚本作为包内资源调用。私有数据位于用户指定的包外目录，升级 skill 不覆盖它。单机单使用者、可创建多人物、一次对话绑定一人物。

依赖顺序：宿主可加载 skill → 可执行辅助脚本 → 可用持久化 → 模型文本能力 → 截图能力。API 密钥由宿主管理，不复制进 skill 或人物数据。

开源的是代码和合成示例，真实聊天、私有资料、数据库、凭据不入仓库。导入到本地不等于全程离线：被加入模型上下文的内容会发往用户配置的模型服务。

### 7.2 文件职责与依赖方向

| 层 | 文件 | 依赖与约束 |
|---|---|---|
| 对话指令 | SKILL.md、references | 引导宿主模型；调用 CLI；不直接写数据库 |
| 入口与契约 | persona_cli.py、contracts.py | CLI 解析请求并分派；不堆放业务规则；contracts 不依赖业务模块 |
| 业务 | materials/profiles/questions/dialogue/memory.py | 调用 validation、storage、contracts；不导入 CLI，不直接调用模型服务 |
| 校验 | validation.py | 纯校验接收已读取的数据；不得主动调用业务流程或执行用户材料 |
| 持久化 | storage.py、migrations | 处理事务与版本；不生成提示、不决定人物性格、不反向依赖业务 |
| 验证 | tests、evals | 测试代码可导入实现；运行时实现不得依赖仓库测试或评测文件 |

业务模块之间优先由入口编排，通过明确的数据与事务上下文协作，避免循环依赖。跨模块的采纳、撤回、删除必须共用一次事务边界，不能因拆文件而分成多个不一致的提交。

`profiles.py` 可编排整个人物删除，但具体 SQL 与文件清理由对应模块提供；不让每个模块各自实现一套人物权限与路径规则。初期规模小可保持少量函数，不为每个实体单建类或 repository 层。

### 7.3 私有运行数据与源码分离

```text
<使用者指定的私有 data-dir>/           # 包外位置，绝不随开源代码发布
├── personas.sqlite3                  # 所有人物的结构化记录；逐查询校验 persona_id
├── attachments/
│   └── <persona_id>/<source_id>.<ext> # 内部 ID 命名，禁止用户名称构造路径
├── tmp/                              # 技能导入临时文件及调用方私有暂存
│   └── imports/                      # 用户选定文件的暂存入口，由调用方清理
└── backups/                          # 显式创建的迁移备份，含敏感信息
```

SQLite 可能生成 journal/WAL/SHM 伴随文件，视为同等私有数据。备份使用 SQLite 一致性备份方式，不直接复制写入中的数据库文件。临时请求文件可能含聊天正文，应放私有临时位置，使用后清理；公共 tests/fixtures 只放合成请求。

人物删除清理主库与对应附件；备份、宿主对话历史的范围需明确告知，不能因源码目录已删除就声称所有资料已清除。测试运行只能使用临时测试目录，禁止连接真实 data-dir。

### 7.4 开发目录、安装目录和发布范围

- 开发时唯一 skill 源码在 `skill/persona-companion/`；不要同时手工维护 `.dsh/skills` 中的第二套源码。
- 安装时将整个 `persona-companion` 包复制到已验证的宿主发现目录，例如项目 `.dsh/skills/persona-companion/`；准确入口按 M0 兼容性记录执行。
- 安装包必须包含 references、scripts 和 migrations，不能仅复制 SKILL.md。包内资源按入口文件位置定位，不依赖运行时工作目录。
- 运行时只依赖包内资源、已验证 Python 运行时和用户指定的数据目录；不通过 `../../docs` 读取开发仓库。
- `operation-contract.md` 随实现从 04 对应契约同步；它是安装包内的简版操作说明，不是另一份独立业务规格。字段变更同时验证两处一致。
- 最小分发包包含 skill 目录、安装说明、隐私说明和合成示例，由 `tools/build_package.py` 按明确清单生成。许可证确认后附带许可文件。开源仓库另含 docs、tests、evals。真实材料、数据库、备份、密钥、临时请求和测试运行产物均在包外。
- 不默认增加前端目录、服务器目录、Docker、CI 或构建框架；有实际需求与验证收益时再增加。

### 7.5 按阶段落地

M0 完成最小加载验证并保留兼容性报告。M1 提供 CLI、契约、校验、存储、人物、材料、版本采纳、撤回、删除和迁移。M2 已接入人物构建、访谈与逐条纠正。M3 完成对话、记忆与发展。M4 补全评测、安装说明、发布检查与验收记录。后续阶段按需创建测试文件。

## 8. 研究借鉴与边界

[Stanford genagents](https://github.com/StanfordHCI/genagents)启发访谈与记忆分工；[Graphiti](https://github.com/getzep/graphiti)启发变化保留历史；[PersonaChat](https://github.com/facebookresearch/ParlAI/blob/main/parlai/tasks/personachat/README.md)启发人物一致性测试。它们不是本期必装依赖，也不构成真实人格还原准确性的背书。
