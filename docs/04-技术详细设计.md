# 04 技术详细设计

版本 v0.4，2026-11-16。M1 已实现本地数据协议，M2 增加访谈和逐条纠正，M3 接入试聊、交流记忆和数字发展。安装包内说明见 [操作契约](../skill/persona-companion/references/operation-contract.md)。架构见 [03](03-系统架构.md)。字段与默认值为设计决策 D。

文件结构与职责以 [03 的项目文件结构设计](03-系统架构.md#7-项目文件结构设计) 为准。CLI 分派与字段定义位于 persona_cli.py/contracts.py；source 操作归 materials.py，profile/persona 操作归 profiles.py，question 操作归 questions.py，chat 操作归 dialogue.py，memory/development/settings 操作归 memory.py；所有写操作共用 storage.py 的事务与 revision 校验。

## 1. 通用数据约束

- ID 使用程序生成的 UUID；显示名称不用于文件名、权限或关联键。时间存 UTC ISO 8601，显示用使用者时区。
- 所有业务记录必须带 `persona_id`，关联查询及写入显式校验同属一个人物。不能只凭记录 ID 修改。
- 字符串 UTF-8；禁止未知枚举、非法字段、空白必填值；不允许模型指定 SQL 或任意落盘路径。
- 人物管理使用递增 `revision`；有审阅依赖的写操作携带 `expected_revision`，不符则冲突。交流摘要以轮次和活动版本做并发校验。
- 来源属性、证据程度与用户采纳状态是三个独立字段。用户采纳不能把推测变成原始事实。

## 2. 数据模型

| 实体 | 核心字段 | 约束 |
|---|---|---|
| Persona | id, display_name, relationship, target_period, address_terms, status, active_version_id, memory_enabled, development_enabled, interview_status, revision, created_at | 名称 1–80 字，关系/时期可 unknown，访谈默认 open，发展开启要求记忆开启 |
| Source | id, persona_id, kind, original_path, original_text, content_hash, context_period, target_speaker, status, created_at | kind=chat_image/chat_text/recollection/hypothetical/style_preference；status=draft/confirmed/withdrawn；图片路径由程序生成，文字保存在本人物记录中 |
| Evidence | id, persona_id, source_id, locator, text, speaker, context, occurred_at, event_key, verification | locator 为图片编号+消息序号或文本段号；verification=pending/user_confirmed；时间和经核对的事件标识可空 |

| ProfileVersion | id, persona_id, version_no, snapshot_json, provenance_json, created_at | 人物内版本唯一、采纳后不可原地编辑；记录 accepted claim IDs 与生成时设置 |
| ProfileProposal | id, persona_id, reviewed_version, claim_ids, unknowns, status, correction_json | 整份候选档案；status=pending/accepted/stale；采纳要求当前修订号仍等于审阅时修订号；逐条纠正附带目标、操作与原因 |
| Question | id, persona_id, target_claim_ids, purpose, text, status, answer_source_id, question_key, skipped_revision | purpose=missing/conflict/context/counterexample；status=pending/answered/skipped；回答生成有类型的 Source 草稿；规范化文字和跳过时的修订号用于避免重复补问 |

| Memory | id, persona_id, session_id, text, kind, source_turn_id, created_at, status | kind=user_update/shared_exchange/agreement；status=active/archived；无历史 Claim 引用通道 |
| DevelopmentProposal | id, persona_id, base_version_id, patch_json, memory_ids, status, reviewed_version, fingerprint | status=pending/accepted/rejected/stale；类别、情境及同组交流依据组成拒绝指纹；采纳在快照中单列数字发展 |
| Operation | request_id, operation, persona_id, payload_hash, result_json, created_at | request_id 唯一；相同 ID 不同载荷返回错误 |
| Audit | id, persona_id, event, object_id, revision, created_at | 只存事件及 ID，不复制敏感正文；人物删除时同步清除 |

`scope` 至少含关系对象、时期、情境；未知写 unknown，不填猜测。`snapshot_json` 包含已采纳特征、未知、临时风格是否接受及其内容。人物删除必须连版本快照、操作结果中的正文一起删除。

不在本地重复永久保存完整模拟对话；仅在记忆开启时存必要交流摘要。宿主是否保存完整消息属于宿主边界。纠正与人物草稿即使记忆关闭也可保存，因为其属于用户主动管理资料。

## 3. 本地操作协议

开发时从仓库根目录采用 `python -E -B skill/persona-companion/scripts/persona_cli.py --data-dir <私有数据根绝对路径> --request-file <绝对路径>`。安装后使用包内 persona_cli.py 的绝对路径。UTF-8 JSON 文件输入，stdout 返回一份 JSON，业务错误退出 1，缺少启动参数退出 2。data-dir 由可信启动配置提供，须独立于技能包目录及其上下级目录。操作由 CLI 分派，Harness 实测通过 `pwsh` 调用。

请求公共字段包括 `schema_version:1`、`request_id`（小写规范 UUID）、`operation`、`persona_id`（create/list 禁用）、`expected_revision`（写操作必需，create 和 memory.record 除外）和 `payload`。请求上限 16 MiB。预览删除要求当前修订号，预览、会话开关及记忆写入不推进人物修订号。

成功：`{ok:true, request_id, data, revision}`；失败：`{ok:false, request_id, error:{code,message,retryable,details}}`。详情不泄露其他人物是否存在。

| operation | payload 关键内容 | data 关键内容 |
|---|---|---|
| persona.create | display_name, relationship, target_period, address_terms | persona_id, status, settings |
| persona.update | relationship、target_period 至少一项 | 原 persona_id、生效字段及活动版本 ID。新范围使用原有范围标签下的结论，区分新旧模拟上下文 |
| persona.list / persona.get | 空 / include_profile（布尔，默认 false） | 人物摘要 / 人物及设置。显式读取档案时包含活动档案、有效待审提案、已采纳纠正、访谈问题、当前材料和证据 |
| source.import | kind, input_path 或 text, context_period | source_id, draft status |
| source.confirm | source_id, corrected_segments, target_speaker | evidence_ids |
| profile.propose | claims（含 evidence_ids、scope、来源）、unknowns | proposal_id, diff, validation_issues |
| question.record | action=create/answer/skip/stop/resume。新建填 purpose、text、可选 target_claim_ids。回答或跳过填 question_id，回答附带 answer.kind、answer.text、可选 answer.context_period | question_id、status、回答对应的 answer_source_id。stop/resume 返回 interview_status |
| profile.accept | proposal_id, reviewed_version, fallback_accepted | profile_version_id |
| profile.correct | claim_id, action=replace/reject, replacement（替换时必需）, reason, apply_immediately（默认 false） | diff, proposal_id, reviewed_version；显式要求立即纠正时同一事务采纳并返回新版本 |
| chat.open / chat.close | 空 / session_id | 会话 ID / 已关闭 |
| chat.prepare | session_id, user_message, 可选范围标签 | 当前版本的轮次绑定、分区上下文、预算及当前开关 |
| chat.validate | 原样轮次绑定 | 复核会话、人物及档案版本有效性 |
| memory.record / memory.list | 轮次绑定、kind、text / 可选分页字段 | memory_id 或 skipped_disabled / 人物摘要列表 |
| development.propose / development.accept / development.reject | patch 和 memory_ids / 后两者填 proposal_id 和 reviewed_version | 前后差异 / 新版本 / 拒绝记录 |
| development.list | 空 | 已采纳的发展、当前待审候选、开关 |
| settings.update | memory_enabled, development_enabled | effective settings, affected proposals |
| source.withdraw | source_id | invalidated_claim_ids, new_version_id |
| persona.delete.preview / persona.delete.commit | 空 / confirmation_token | 数据范围与短期 token / 删除结果 |

`profile.propose` 接收完整候选档案。结论的 `scope` 包含 `relationship`、`period`、`context`。引用字段为 `evidence_ids`（支持）与可选的 `contradicting_evidence_ids`（反例）。提案不改变活动版本，返回实际展示的 `reviewed_version`，即提案提交后的修订号。`profile.accept` 只能采纳用户实际审阅的版本，资料不足时须确认临时风格。删前预览 token 绑定人物、revision，有效期 10 分钟。

M1 实现人物、材料、档案和删除操作，M2 接入访谈与逐条纠正，M3 实现对话、记忆、发展和开关。

## 4. 核心逻辑

### 4.1 归纳与证据不足

1. 只使用已确认说话人和转录的材料；按事件分组，不将同一事件十条消息当作十个独立事例。
2. 优先提取直接表达和情境行为；稳定性格必须说明跨事件依据。不规定虚假的科学条数阈值。
3. 输出每项结论、来源、反例、适用范围。没有材料支持的内容保留 unknown，用户设定单独标记。M1 要求 `supported` 的稳定性格至少关联两个不同的用户核对事件标识，假设回答仅支持 `tentative` 的情境候选，反例未解决时只能保留初步推测。事件标签用于去重和校验，语义与事件独立性仍须由用户核对。
4. 用户自定义风格可无历史证据，但必须 origin=user_defined。supported 的推断必须至少有一个有效引用；有引用只是必要条件，不代表心理测量有效。
5. 按“影响近期对话 → 材料冲突 → 信息缺失”排序补问。已跳过的问题只有在出现新核对且仍有效的相关历史来源时才可重提。CLI 按规范化问题文字去重，skill 同时检查语义重复和相关性。回答先保存为草稿来源，使用通用核对操作生成证据。

历史引用有已知时期时校验结论的时期。明确冲突的提案应重新核对，既有错期快照退出试聊。用户结束访谈或转入试聊时，记录 `stop` 并将余下待答题转为跳过。关闭后阻止新问题，用户明确要继续时使用 `resume`。

### 4.2 回复构造

按明确标记的区域组织：系统规则、人物版本、原始材料（不可信输入）、交流记忆（模拟来源）、用户当前消息。选择匹配关系/时期/情境的材料。未知部分使用已接受的临时风格，不生成确定的真实经历、意愿或承诺。

试聊上下文带访谈状态，关闭时明确要求停止回忆补问。访谈状态切换使旧轮次失效。关系或时期变更时追加活动档案版本，保留原结论标签，归档旧模拟记忆及发展并使旧轮次失效。

生成前固定 `profile_version_id`。CLI 返回签名绑定，由人物、会话、轮次、版本、到期时间和准备时的记忆开关组成。输出前复查人物状态、当前版本、会话及绑定。在采纳纠正、撤回影响当前版本的来源、删除、切换并关闭旧会话或轮次过期后，旧待发回复应丢弃。宿主负责把最终校验放在输出之前，并检查其当前选中的人物。模型请求期间不持有写事务。

### 4.3 记忆与发展

新回忆进入 Source；新互动进入 Memory。AI 的“我喜欢某事”只能属于模拟对话，不能变成真实人物 fact/trait。用户肯定一次模拟回答也不自动证明历史事实。

development_enabled=false 时不生成发展提案；开启时生成候选 patch，保持基础历史层不变。用户采纳后生成数字发展层的新版本；只改变模拟表现，不回写历史。拒绝候选保留拒绝指纹，避免相同依据重复请求。

轮次准备时及写入时均须开启记忆。关闭记忆要求同时显式关闭发展。已有记忆保留且可查看，活动摘要仍可用于交流。历史档案采纳、纠正生效或撤回影响当前档案时，旧摘要归档，数字发展随旧版本保留并退出当前上下文，避免以模拟内容重新激活旧结论。

### 4.4 撤回与纠正

撤回 Source 后重新检查关联 Claim。支持不足或仍有反例则标为 needs_review 并从活动档案移除。仍有效的结论保留，其引用排除撤回证据。有活动结论受影响时生成新版本，旧提案失效。最后一条已知结论移除且临时风格未获接受时，人物返回草稿。当前读取过滤已撤回材料，历史快照、来源与附件保留在私有存储中，整个人物删除时一并清除。

纠正以本人物的当前已采纳结论为目标。替换结论保留 `supersedes_id`，其来源由通用结论校验处理。拒绝保留 `rejected` 状态；其余活动结论 ID 保留。提案阶段原版本继续生效。用户明确要求立即处理时在同一事务提交新版本，沿用既有临时风格设置。已生效纠正可随档案读取，用于后续归纳时排除旧结论。

## 5. 鉴权、隐私与安全边界

本地单用户，无 JWT、密码或远程 HTTP 接口；依赖操作系统权限与宿主工具授权。脚本校验数据目录、人物归属、操作类型。共享 OS 账号无法隔离不同人；不以提示词宣称安全隔离。

文件导入仅从 `data-dir/tmp/imports` 读取用户选定并由调用方暂存的文件。支持 PNG/JPEG/WebP 和 UTF-8 `.txt`，按扩展名、文件结构或文本编码校验。单图 10 MiB，单文本 2 MiB，图片结构校验由标准库完成，像素解码和内容辨认可在宿主阶段验证。拒绝路径穿越、符号链接、Windows 重解析点及多重硬链接文件。导入暂存原件和请求文件由调用方清理。

数据库不存模型凭据；会话签名密钥保存在私有库，只用于核验本地轮次。日志不含聊天正文。默认不联网安装、不做遥测、不上传资料到新增服务。材料传入宿主模型前展示数据流向；新增 OCR 服务由 Q03 决定。SQLite 默认未加密，不宣称已提供静态加密；使用者可借助 OS 加密磁盘保护。

## 6. 一致性与错误处理

- SQLite 外键开启；一次资料采纳及版本指针更新在同一事务内。模型请求不占用写事务。
- 本地写操作串行执行；optimistic revision 防止两个会话互相覆盖。冲突时重新读取，不自动合并用户意见。
- 成功写入的同一请求返回原结果，同 request_id 不同请求返回 REQUEST_REUSED。读取返回当前状态，读取请求 ID 不入账。
- 已校验附件先写临时文件、刷盘并原子重命名，再登记数据库。中断留下的孤儿文件在该人物下次导入或删除时清理，清理与导入都持有 SQLite 写锁。
- 人物删除先持久化 pending 标记并停止读取，然后清理附件与数据库依赖。失败后保留原请求并重试，全部完成才返回 deleted。成功后只保留无正文的请求墓碑，旧创建请求重放也不能重新创建人物。
- 删除预览列出清理范围以及排除项，后者包括宿主历史、备份、请求文件和导入暂存原件。
- M1 初始迁移记录 `PRAGMA user_version=1`，M2 推进到 2，M3 推进到 3。本轮修复升至 4，旧人物的访谈状态默认为 open。CLI 请求的 `schema_version` 仍为 1。迁移和版本标记在一个事务中提交，拒绝未知版本及非空的未版本化数据库。迁移前暂停写入，用 SQLite 一致性备份并保存对应附件，回退时成套恢复脚本、数据库与附件。

| 错误码 | 行为 |
|---|---|
| INVALID_INPUT / SOURCE_UNREADABLE / SPEAKER_UNKNOWN | 指明需纠正项，不更新活动档案 |
| CAPABILITY_MISSING | 指明模型/图像/脚本能力缺失；截图 P0 不算完成 |
| MODEL_FAILED / OUTPUT_INVALID | 不落地部分结论，可重试，不无限重试 |
| REVISION_CONFLICT / PROPOSAL_STALE | 重新读取并展示差异 |
| PROFILE_NOT_READY / TURN_STALE | 先采纳档案，或丢弃已失效回复并重新准备 |
| INVALID_SETTINGS / DEVELOPMENT_DISABLED / DEVELOPMENT_REJECTED | 拒绝无效开关组合、关闭发展时的候选及重复提交的已拒绝候选 |
| PERMISSION_DENIED / NOT_FOUND | 不泄露其他人物信息 |
| STORAGE_BUSY / STORAGE_FAILED | 保持旧版，有限重试，明确未保存 |
| CONFIRMATION_REQUIRED / CONFIRMATION_EXPIRED | 重展示具体操作范围 |
| REQUEST_REUSED / SCHEMA_UNSUPPORTED | 请求 ID 已占用，或当前脚本与数据库版本不兼容 |

## 7. 性能与容量（工程目标，待测）

本地 10 个人物、每人 1,000 条证据、1,000 条记忆作为首轮负载；本地查询/写入 p95 小于 1 秒，不计模型时间，并记录测试硬件。上下文只选择相关材料，禁止每次全量附件发送；不得静默截断关键证据。模型时间记录分布，超过 30 秒给进度，120 秒可取消/重试；真实超时设置按宿主能力落实，不承诺模型必在该时限完成。
