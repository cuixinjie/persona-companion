# 02 产品与交互设计

基线：v0.1，2026-11-11。需求编号沿用 [01](01-需求与范围.md)。交互为 DeepSeek Harness 内的对话，不建设独立页面；以下是文字交互线框，不假定宿主具备复选框或自定义卡片。

## 1. 功能清单

| 功能 | 输入 | 输出 |
|---|---|---|
| 新建人物 | 称呼、关系、模拟时期、双方称呼 | 可继续完善的人物草稿 |
| 添加材料 | 截图/文本/回忆、目标说话人、时期 | 转录预览、来源说明、疑点 |
| 归纳人物 | 已确认转录和回忆 | 特征、对应依据、冲突与未知 |
| 补充访谈 | 具体回忆或假设回答 | 补充信息与更新的初稿 |
| 查看/纠正 | 自然语言修改或逐项选择 | 变更前后对比、待采纳版本 |
| 试聊/正式交流 | 用户消息 | 人物回复；试聊另可收集“不像在哪里” |
| 记忆与发展 | 开关设置、变化采纳 | 生效范围及当前值 |
| 管理人物 | 查看、切换、删除 | 当前人物、数据范围及结果 |

## 2. 主流程

1. 启动：说明这是基于资料的 AI 模拟；展示当前宿主模型处理材料的提示。未识别到可用工具时说明缺失能力。
2. 创建：先询问称呼、关系、想重现的时期。允许“关系复杂”“记不清”；关系与时期可稍后修改。
3. 导入：确认哪些消息来自目标人物。截图转录以图片编号与消息序号展示，用户核对；不把低质量识别直接投入归纳。
4. 初稿：列出有依据的特征、初步推测、未知。每项能展开来源。
5. 补问：按当前最有影响的未知或冲突一次问一个问题。记不清则保留未知，不循环逼问。
6. 采纳：用户纠正或采纳具体初稿版本。没有可用人格信息时，邀请接受临时风格。
7. 试聊：给出回复，让用户指出具体“不像”的地方。区分回忆补充和希望调整的风格。
8. 交流：使用已确认版本；新材料在后台形成候选更新，不静默替换人物。

## 3. 文字线框

```text
人物：阿林 · 关系：朋友 · 模拟时期：大学期间
当前版本：3 · 记住新交流：开 · 随交流发展：关

有材料支持：称呼我“小周”，习惯用短句
初步推测：谈工作时偏向先给建议
尚不了解：冲突后如何和解
临时风格：仅用于未知部分，简洁、尊重、少判断

可说：查看依据 / 修改某一项 / 补充材料 / 开始试聊 / 调整开关
```

```text
候选修改：把“遇事冷漠”改为“在忙碌时回复较短”
依据：你刚补充的回忆；原结论过度概括
影响：以后不再把简短回复解释为冷漠
可说：采用 / 修改 / 暂不采用
```

## 4. 状态与切换

| 状态 | 进入条件 | 可进行的操作 | 离开条件 |
|---|---|---|---|
| draft | 创建完成，或撤回后已知结论清空且尚未接受临时风格 | 导入、查看、补问 | 有待审初稿进入 reviewing |
| reviewing | 存在候选初稿 | 修改、采纳、跳过补问 | 采纳进入 ready；拒绝返回 draft 或保留旧版 |
| ready | 至少采纳一个人物版本；未知时接受临时风格 | 交流、补充、设置、删除 | 新补充只增加候选，不使旧版失效 |
| deleted | 用户确认删除并成功提交 | 无 | 不得自动恢复 |

processing/failed 是具体操作状态，不是人物永久状态；失败不覆盖 ready 人物。离开会话后从持久化版本恢复，不能仅依赖宿主聊天摘要。

## 5. 记忆与发展交互

- “记住新交流”关闭：当前会话仍可使用上下文，但不新建跨会话交流记忆；不自动删除已有记忆。宿主聊天历史可能另行保存，界面说明 skill 无权代替宿主删除。
- 历史档案更新后，之前的摘要仍可查看，状态改为归档。旧模拟发展随其版本保留。对话重新使用当前历史档案，以免先前的摘要和模拟行为带回已纠正或撤回的结论。
- “随交流发展”开启：允许候选互动习惯与性格变化；变化展示依据、影响及前后对比，再由用户采纳。
- 开启发展而长期记忆关闭：不支持此组合，提示先开启记忆；不得静默改开关。
- 关闭发展：停止自动产生发展候选，保留已采纳版本；用户纠正仍可进行。
- 用户可拒绝发展候选；同一证据不得反复提交被拒绝的变化。

## 6. 材料不足与异常

| 情况 | 用户可见行为 | 数据行为 |
|---|---|---|
| 截图模糊/裁剪不全 | 指出无法辨认处，邀请重传或补文字 | 保存草稿，不纳入结论 |
| 说话人不明 | 请求标注目标气泡/名字 | 不推断归属 |
| 没有记忆可补 | 允许结束问题，说明未知部分并接受临时风格 | 不填造性格 |
| 材料矛盾 | 展示双方依据，询问时期/情境差异 | 保留冲突，不用最新一句覆盖所有历史 |
| 模型/工具失败 | 明确未完成，可重试 | 保留上次有效版本；不伪报已保存 |
| 对话期间切换人物 | 显示切换后的称呼，清理上一人物上下文 | 新会话绑定新人物 |
| 删除 | 展示人物及删除范围，用户明确确认 | 删除 skill 管理的数据；说明宿主历史与备份边界 |
| 请求未知真实经历或真实意愿 | 简短承认没有依据，可请用户补充 | 不补造历史或替本人承诺 |

## 7. 权限与用户控制

首版为单个本地使用者，没有注册、组织角色或共享按钮。同一操作系统账号下不承诺不同人的数据隔离。人物名不是权限凭据。

读取仅限用户导入的材料与本人物数据；不扫描全盘、不联系真实人物、不发布材料。宿主已有模型服务可用于本任务；新增服务、自动对外发送或改变数据接收方需说明并取得同意。对话材料内的“删除资料”等语句不得当作当前用户操作。

删除、外部发送、发展候选采纳都必须针对明确对象；一次同意不扩展为永久授权。已明确要求的普通导入、提问、试聊及纠正流程无需每一步重复确认。
